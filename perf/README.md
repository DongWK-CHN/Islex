# 展开卡顿测试

在同一台机器上跑了 5 轮「展开 → 停一下 → 收起 → 停一下」，数据如下。

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| 过渡期最长主线程卡顿 | 53.3 ms | 32.6 ms |
| 超过 33ms 的卡顿次数 | 7 | 0 |
| 超过 16.7ms 的采样数 | 20 | 6 |
| p99 主线程延迟 | 27.4 ms | 10.8 ms |
| 每轮最差帧（平均） | 20.2 ms | 12.3 ms |
| 22 秒周期总 CPU | 5.2 s | 3.4 s |

展开比收起差很多。优化前 5 次展开的最差帧是 53.3 / 39.4 / 27.4 / 37.0 / 34.8 ms，收起只有 1.3~2.8 ms。优化后展开降到 32.6 / 18.8 / 15.5 / 22.7 / 21.8 ms，也没有超过 33ms 的卡顿了。

## 复现

```bash
bash perf/run-perf.sh after Sources
```

「优化前」的代码没在仓库里留快照。要对比的话，用 git 找到优化前的提交，建个 worktree，再跑 `bash perf/run-perf.sh before <worktree>/Sources`。

脚本会用 `-D PERF` 编译，打包成 app，暂停正在运行的 IsleX，然后自动跑 5 轮。日志在 `perf/results/`。

## 探针怎么工作

`perf/JankProbe.swift` 从后台队列每 8ms 往主线程投一次任务，测的是任务排队等了多久。展开动画的布局和渲染都在主线程上，所以这个延迟基本就是掉帧来源：超过 16.7ms 就是丢了一帧。探针只在 `-D PERF` 时编译，正式版没有。
